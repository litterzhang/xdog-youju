# Client Navigation and Onboarding UI

## Direction

This redesign references the local `zdog-mp/zdog-client` layout: light-gray page
surfaces, white grouped cards, compact list rows and restrained typography. It
retains Youju's monochrome constraint: no colored accents, gradients, decorative
shadows or emoji. The reference repository was read only and not modified.

All page titles use Taro page configuration and the mini-program's **native
navigation bar**. There is no in-page brand/title header or custom navigation bar.
Section labels, source identity and workflow progress are content, not duplicate
page titles. H5 uses Taro's corresponding navigation implementation.

## Ordinary-user tabs

Native `tabBar` configuration defines exactly three tabs, with small local grayscale
PNG icons and no custom tab implementation:

- **首页**: official-evidence principles, a saved-job entry and reading tips.
- **岗位**: audited saved-job search/list/detail with expiry filtering, evidence and
  explicit partial-material opt-in. Unknown terms never imply current vacancies.
- **我的**: fresh identity verification, account-ID copying, login/logout and service
  connectivity. The administrator entry appears only here and only after a server
  response grants `youju:source:manage`; no cached browser flag grants access.

Login returns to 我的 through `switchTab`, rather than rebuilding the old home stack.
Service connectivity is not presented as announcement freshness.

## Independent administrator flow

The former long, combined admin form is replaced by separate native-title pages:

1. **来源管理**: paginated registered sources, recorded state and a new-source entry.
2. **确定组织**: choose an existing organization or register its identity/root domain.
   **登记地区** is a separate auxiliary page that returns to this form.
3. **登记来源**: source identity, HTTPS entry, optional region tags/seeds/description.
4. **来源核验**: record literal official-publisher evidence and explicitly approve;
   task submission is a separate confirmation, never implied by registration.
5. **采集进度**: acquisition/classification/authoring/audit/incremental timeline,
   complete/partial counts, expiry/application rules, warnings and blocking errors.

Each admin page freshly checks permission; hidden-page responses are invalidated.
The visible status page polls every 15 seconds and stops while hidden. It reuses the
existing protected server APIs. Form selections retain IDs rather than list indices.
Canceling approval/task confirmation does not save or submit a task. Earlier-stage
completion does not claim that every resource parsed successfully. No worker or
model is launched by viewing or refreshing these pages.

would publish UI changes, so verification uses an operator-only staging override:

```sh
YOUJU_CLIENT_OUTPUT_ROOT=/absolute/project/path/server/.artifacts/ui-check/h5 \
  npm --prefix client run build:h5
YOUJU_CLIENT_OUTPUT_ROOT=/absolute/project/path/server/.artifacts/ui-check/weapp \
  npm --prefix client run build:weapp
```

## Verified account profile display — October 14, 2026

The 我的 account card now displays the verified zdog-auth username and avatar
when available. `/api/auth/me` projects only the optional `username` and `avatar`
fields, not the entire upstream profile. Invalid optional fields are omitted
without invalidating login; usernames are bounded and avatars require HTTPS.
Profile fields do not participate in permission checks.

Missing usernames retain 已登录; missing or failed avatars retain the neutral
person icon. Avatar and username are independent, so either can display alone.
Taro Image supports both H5 and weapp without platform-specific globals.

## Session recovery and navigation arrows — October 14, 2026

WeChat 0.1.5 follows Xiaoman's authenticated transport pattern: on a 401, one
shared native WeChat login/code exchange restores the same verified subject and
retries the rejected request at most once. Subject mismatch, logout/account switch,
repeated rejection or identity-less legacy expiry requires explicit login. A local
generation fence also rejects logout/login races with the same token. Network,
503 and 403 failures do not trigger relogin or erase a usable session. Passwords
and permission grants are not stored. The API independently rechecks permissions.
H5 cannot silently exchange a WeChat code and keeps explicit password login.

Verified sessions persist token and subject together. Valid legacy tokens migrate
on a successful identity check; already-expired old token-only sessions require
one explicit login after upgrade before safe automatic recovery is available.
Left/right pagination, menu and picker arrows use four packaged monochrome PNGs,
not platform fonts or CSS-only chevrons. The existing tab PNGs were not regenerated.

TypeScript and nineteen client tests passed; staged H5 and official weapp upload
passed. Synthetic H5 checks covered storage, both pagination directions, loaded
arrow images and explicit H5 expiry. Native silent renewal/device behavior remains
unverified. Upload 0.1.5 succeeded at 15:26:18 Asia/Shanghai, 384.5556640625 KB.
No backend restart, H5 replacement, review or release was performed.
